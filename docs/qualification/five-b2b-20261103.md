## Setup before enabling

1. Install Google Workspace (qualified release `0.3.3`) and, except for feedback tagging, Outgoing Email/SMTP (`0.3.1`). Import resolves the native package references to an actual install; no source installation IDs are supplied.
2. Configure project-scoped connections and supply their reference IDs through the workflow's declared callable inputs. Supply spreadsheet IDs, table/schema fields, recipients, trusted time, and other required inputs described by the callable interface. No credentials belong in the template YAML.
3. Select the importing project's AI model for the security intake/monthly review, KPI summary, and feedback tagging agents. Models are intentionally omitted by the canonical exporter. Validate and enable all required included agents, skills and children before enabling the parent.
4. Configure the intended schedules or forms separately. Until then, these are callable workflows. The incident templates deliberately have separate entrypoints.
5. Validate the configured draft and perform a controlled provider test before operational use. No live OAuth, scopes, provider responses, model quality, production import, queue persistence or recovery is proven here.

Every read is bounded to 100 rows per table and requires a complete preview. Larger inputs stop processing. Table overwrite requires dedicated contiguous plain-value tables and a single writer; formula preservation, formatting preservation and concurrent edits are outside the qualified profile. Header rows count toward native inline write limits. SMTP replaces Gmail sending: Gmail thread and Sent-folder behavior is not reproduced. Sending mail and recording its stage are separate effects; after uncertain results, reconcile instead of blindly retrying.

## What the offline run proves

The final publication artifacts are produced by the production `WorkflowPortabilityService.export_yaml` using in-memory fixture persistence from Core `21601831d5f816e94f7ba2135585715f96f80316` (`0.9.9`). Graph topology, control bodies, callable settings, input/output mappings, error policies and business overrides are compared to the earlier qualified drafts. Authoring aliases `agent`/`skill` are normalized to canonical persisted fields `agent_id`/`skill_id` before export. Connector symbols become native package and operation references, preserving their released contracts. The KPI skill uses the supported `data` category.

Real import preflight is exercised against an empty fixture installation. Missing extension installs are expected setup requirements, not successful imports. Structural/configuration/selector validation and carried definitions are checked independently.

The execution host constructs a graph from the actual production orchestrator/step nodes for the selected pinned definition. It uses the real Template, Transform, control-flow, ForEach/Batch/Collect, Invoke and PromptAgent implementations and released Workspace/SMTP handlers. The actual portability step rewrite maps logical extension dependencies to test installation references; native extension/action derivation is exercised before dispatch. Only the provider/model transports and explicitly declared host boundaries are synthetic.

Fixture boundaries include registry/installation/connection/auth/grant/effect-ledger persistence, in-memory artifacts, a scripted model client and synchronous nested child launch. This does not exercise the live worker/bootstrap, workflow intake/routing, broker persistence or durable exactly-once effects. Fixture checkpoint storage uses official MemorySaver save/read operations while retaining two physical snapshots; each checkpoint is checked before historical garbage collection. Long-history replay/durability is unverified. The runtime container has no network, and socket attempts are rejected.

The catalog's `verification_status` badge is not a live-provider guarantee. The exact final artifact hashes and final execution counts are recorded in the adjacent qualification JSON.
